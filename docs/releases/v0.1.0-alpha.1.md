# v0.1.0-alpha.1

First public prerelease of Computerworld: one deterministic Rust simulator for
native Rust, Python, Node and browser Wasm. Python represents this version as
`0.1.0a1` under PEP 440.

## What is included

- Generic serialized worlds with multiple computers, OS profiles, filesystems,
  processes, shell execution, applications and deterministic time/randomness.
- Synthetic DNS, routing, HTTP, independent persistent services and network traces.
  Host networking requires an explicit capability adapter and policy.
- Restricted agent environments, owner/evaluator inspection, recorded trajectories,
  reset, snapshots, restore and forks.
- Compact structured scenes and optional deterministic rasterization, plus five
  interactive OS-inspired desktop/mobile profiles. Desktop windows move, resize,
  stack, minimize/maximize/restore and snap; mobile profiles support app navigation.
- Thin Python and JavaScript bindings, programmatic computer-use demos, and a
  client-side multi-device browser console. No simulation backend is required.
- A reference company world and optional mail, documents, chat, calendar, Git,
  issues and website service packages.

## Install a pinned version

Use the assets on the [GitHub prerelease](https://github.com/JacobFV/computerworld/releases/tag/v0.1.0-alpha.1).
Select a Python wheel compatible with your platform, or a Wasm bundle for browser
and Node use. Planned wheel targets are Linux x86_64 (manylinux2014), macOS arm64
and Windows x86_64, using CPython 3.9+ abi3. Only successfully built and tested
platforms are uploaded. The asset list is authoritative for available binary platforms;
source builds remain available when a compatible wheel is absent. See
[Python](../python.md) and [JavaScript/Wasm](../wasm.md) for installation and examples.
There is no PyPI, npm or crates.io publication in this release.

For source:

```sh
git clone --branch v0.1.0-alpha.1 --depth 1 https://github.com/JacobFV/computerworld.git
cd computerworld
```

Rust consumers can pin the Git tag in their Cargo manifest:

```toml
[dependencies]
computerworld = { git = "https://github.com/JacobFV/computerworld.git", tag = "v0.1.0-alpha.1" }
```

## Compatibility and limitations

This is an alpha for technical early adopters. Public APIs, world schemas, action
families, observations, renderer output and snapshot serialization may change in
the next prerelease. Keep the engine version, world definition, seed and action
sequence together. Checkpoints are supported with the exact runtime version that
created them; cross-version restore or identical pixel output is not promised.
A schema version field is not a migration guarantee.

Python requires CPython 3.9 or newer and a compatible wheel, or a Rust toolchain
for a source build. The source declares Rust 1.88 as its minimum; release CI uses
stable Rust, Python 3.12 and Node 22. Not every intermediate toolchain is tested.

The OS views are synthetic, not vendor operating systems or pixel-perfect replicas.
Bundled fonts differ from system fonts, application controls are bounded, and some
controls are explicitly disabled. Arbitrary native binaries, arbitrary HTML/JS,
native mobile SDKs, camera/phone hardware and a full TCP/IP implementation are
outside this release. See [desktop fidelity](../desktop-gui.md#rendering-and-fidelity),
[computer semantics](../computers.md), and [security boundaries](../security.md).

## Verification and provenance

Release publication requires successful CI and artifact smoke checks described in
[the release process](../releasing.md). Checksums identify the downloadable files;
the Git tag identifies their source. CI logs provide the actual test/build results
and platform matrix rather than implying that every platform combination was run.
The browser suite checks real pointer/keyboard interaction after blocking episode
networking; binding checks compare Python/Node semantic state and pixel output.

Bundled project, font, icon and wallpaper notices must accompany redistributed
artifacts. Their licenses are independent of the simulator's MIT license.
Predecessor analysis and retained semantics are documented in
[provenance](../provenance.md) and [migration notes](../migration.md).
