README.md

fixpoint

buildpassing crates.iov0.9.2 docslatest coverage87%

A deterministic fixed-point layout kernel. Every length is a i32 in 1/64 px, every arithmetic step rounds the same way on every platform, and the output of a layout is a function of its input alone: no floats, no host fonts, no wall clock.

Installation

Add the crate to your Cargo.toml:

[dependencies]
fixpoint = "0.9"

[features]
default = ["flex", "grid"]

Quick start

use fixpoint::{Au, Box, Constraints, layout};

let root = Box::block().width(Au::px(640)).children(vec![
    Box::inline_text("hello"),
    Box::block().height(Au::px(24)),
]);
let tree = layout(&root, Constraints::viewport(640, 480));
assert_eq!(tree.root().size().height, Au::px(43));

Features

  • Fixed point everywhere. Widths, heights, offsets and text advances are all quantised to 1/64 px before they enter the tree.
  • Block, inline, table, flex and grid formatting contexts, with the CSS 2.1 margin collapsing rules and clearance.
  • Deterministic text shaping through the bundled faces; glyph advances are read from the font tables and never from a rasteriser.
  • Reftest driven. The tests/ref corpus pairs each feature with a reference document that must paint to the same pixels.

Stability

The public API follows semantic versioning. The layout result for a given input is part of that contract: a patch release never changes a single pixel of an existing fixture, and a minor release may only change pixels for documents that use a newly supported property.

Contributing

Open an issue before a large change. Every pull request needs a reftest pair under tests/ref and must keep the parity numbers in target-parity/report.md from going down.
