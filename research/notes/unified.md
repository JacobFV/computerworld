## Most important actual-versus-claimed findings

1. **Determinism is not global.** Simulation constructor seeds fabric RNG from runId (`simulation.ts:55–56`), network has mulberry32 (`network.ts:206`) and injectable clock (`:478`). But IDs use node randomUUID throughout VFS/network/apps/collaboration; new Date/Date.now stamp semantic state and trajectory. `ProcessManagerOptions.clock` exists (`processes.ts:108`) but is never read by constructor (`:138`), and nowIso uses wall time. UI intranet animation uses performance.now. Same seed/action sequence cannot reproduce byte-identical trajectories here.
2. **Snapshot means observation.** `SimulationSnapshot` (`protocol:648`) omits file contents, inode graph, complete service state, browser state, RNG/counters and pending execution. `simulation.ts:605` has no restore counterpart. VFS separately restores host metadata journal (`vfs.ts:151`); that is persistence, not world fork/replay. Trajectory recorder (`trajectory.ts:9`) records wall time then hashes full JSONL; no action replay executor. A new Rust checkpoint API is required.
3. **Generic topology inversion is good but incomplete.** Kernel imports `@seed/catalog` (`simulation.ts:9`), calls `registerSeedServices` and `seedCollaboration` (`:72–73`), initializes `/seed/example.git` (`:66`), seeds task/demo/pdf files unconditionally (`:159–166`), embeds a full intranet HTML/CSS/JS fixture (`:168ff`), and installs services derived from global app catalog (`:305ff`). Initialization rewrites these fixture files even on resumed disks. Closed `OSKind` and `SimulationServiceKind` enums impede arbitrary extension. Core must consume opaque registered definitions/serialized initial state, not this catalog.
4. **Service quality is uneven.** Independent Slack/Teams stores and actual network access are real; generic catalog services are an in-memory events array with POST append and GET dump (`simulation.ts:305–316`), not full mail/docs/calendar semantics. No persistence/restore for gitRemotes/genericServiceState maps. Port richer synthux service logic as optional modules where evidence warrants it.
5. **Browser is still Chromium projection.** Server fetches top-level page through runtime.http, caches documents and serves them into sandboxed iframe. BrowserApp renders iframe with `allow-scripts allow-forms allow-popups` (`:286`); tabs/history live in client application state. There is no core browser runtime or renderer contract. This path is suitable as a benchmark baseline/optional compatibility example, not canonical semantics.
6. **Core portability is low despite useful boundaries.** VFS depends on node fs/path/crypto and one blob per inode; application engine spawns workers/vm and has optional subprocess gateway; network imports host DNS/HTTP. All should become pure Rust state + capability adapters, not translated host calls. Simulator's ChatGPT route directly fetches Anthropic (`server/index.ts:244`) outside fabric; remove that app-specific host coupling from reusable architecture.
7. **Good causal semantics worth preserving:** network per-computer loopback isolation; process exit unregisters owned listeners (`simulation.ts:114`); package install materializes executable descriptors; Git pushes carry objects enabling another computer's worktree; capability denial precedes syscall handler dispatch; service HTTP path connects UI operations and shell observations.
8. **Avoid excess network fidelity.** HEAD traces sequence/ACK/window, ARP/NDP, NAT, MTU fragmentation and retries. The reusable engine should retain causal reachability/transport semantics but make trace-detail optional; this is not evidence that packet-level emulation is required for ordinary agent training.

## Candidate Rust interfaces inferred from the evidence

- `WorldDefinition { schema_version, profiles, computers, service_instances, dns, routes, policy, initial_state }`, validated generically with registration of separately packaged app/service types.
- Pure `Runtime { clock, deterministic_ids, rng_streams, scheduler, computers, network, apps, services }`; explicit deterministic tick + event queue, not futures ordered by host scheduler.
- `Vfs` accepts bytes/identity/path operations. Immutable shared blob backing + copy-on-write graph; host disk checkpoint writer is external adapter.
- `Service::handle(context, request) -> (response, effects)` with explicit instance state and DNS/network ownership; no knowledge of accessing OS/browser.
- `Network::request(source, request)` and `HostAdapter::execute(authorized_request)`; no adapter means impossible outbound access. Preserve rebinding/redirect constraints.
- App model handles semantic events and emits compact scene + semantic tree; pointer/keyboard routing by interaction IDs. Rendering never mutates simulation state or consults host clock/fonts.
- `Checkpoint` must carry entire resumable state and be distinct from `Observation`; event journal carries sequence/logical time and stable causal IDs. Actor interface capability filtering belongs above runtime; privileged inspector is a separate handle.

Best reuse is algorithms, invariants, schemas and tests—not the monolithic simulation.ts, product catalog dependency, Node storage architecture, or copied React surfaces.
